## 실패 결함

### D-01 — Focus 완료 카운트가 메모 제출 전에는 증가하지 않음

- 위반 PRD: FR-03 처리 순서(완료 카운트 증가 후 Memo-Input-Pending), FR-05, §13.1
- 검출: `T-FR03-01`
- 위치: `gemini포모도로.html:1365` (Focus 완료 분기), `:1393`, `:1399`
- 재현: Focus를 시작하고 종료시각까지 경과시킨 뒤, 메모를 제출하거나 건너뛰지 않는다.
- 기대: 즉시 해당 날짜 완료 수가 1이고 Memo-Input-Pending 상태가 된다.
- 실제: Memo-Input-Pending 상태는 되지만 로그/완료 수는 0이다. 기록이 메모 제출·건너뛰기 시점까지 지연된다.

### D-02 — 메모가 완료 시각이 아니라 제출 시각의 날짜에 기록됨

- 위반 PRD: FR-05(완료 시각과 함께 해당 날짜 로그에 추가), FR-06, FR-08 §286
- 검출: `T-FR05-02`, `T-EC03-05`
- 위치: `gemini포모도로.html:1393`, `:1399`
- 재현: Focus가 자정을 넘겨 종료된 뒤 다음 날까지 Memo-Input-Pending으로 두고 메모를 제출한다. 재접속으로 이미 만료된 Focus에서도 동일하다.
- 기대: 메모는 원래 `endTimestamp`의 로컬 날짜·완료 시각에 있는 단일 완료 기록에 붙는다.
- 실제: `Date.now()`인 제출 시각으로 새 기록을 만든다. 원래 날짜 기록은 빈 메모로 남거나, 정상 완료에서는 원래 날짜 기록 자체가 없다.

### D-03 — 재접속 시 만료된 Focus가 중복 기록되고, 메모 뒤 다음 세션을 자동 시작함

- 위반 PRD: FR-08, EC-03, BR-02, §13.2 재접속 복원 시나리오
- 검출: `T-EC03-03`, `T-EC03-04`, `T-EC03-05`
- 위치: `gemini포모도로.html:1239`, `:1393`, `:1399`, `:1412`
- 재현: Running Focus의 `endTimestamp`를 과거로 저장한 뒤 앱을 재접속하고, 메모를 제출 또는 건너뛴다.
- 기대: 만료 Focus는 원래 종료시각에 **1회만** 완료 처리하고, 메모를 연결한 다음 Short/Long Break를 Idle로 대기시킨다.
- 실제: 재접속에서 빈 메모 완료 기록을 1회 만든 뒤 메모 제출에서 1회 더 기록하여 총 2회가 된다. 또한 다음 Break를 `start()`로 자동 실행하여 `Running`이 된다.

### D-04 — 실패한 특정 localStorage 쓰기가 이후 상태 변화에서 재시도되지 않음

- 위반 PRD: EC-05
- 검출: `T-EC05-02`
- 위치: `gemini포모도로.html:908`, `:911`, `:1125`
- 재현: `pomodoro_settings` 쓰기만 1회 실패시킨 뒤 설정을 7분으로 저장하고, 실패 조건을 해제한 뒤 타이머를 시작한다. 이후 새로고침한다.
- 기대: 다음 상태 변화에서 실패했던 설정 쓰기도 재시도되어 저장되며, 새로고침 뒤 Focus 설정은 7분이다.
- 실제: 타이머 상태 키의 성공 쓰기가 전역 실패 상태만 해제한다. 설정 키는 재시도되지 않아 새로고침 뒤 기본값 25분으로 돌아온다.

## 미실행

- 실제 Chrome/Edge/Firefox에서 `file://`로 열었을 때의 localStorage 정책·저장 실패 UI·Notification API 호출. 브라우저 제어 런타임이 초기화되지 않아 실행하지 못했다.
- OS/브라우저 설정에 따른 실제 데스크톱 알림 표시 여부. PRD §3.2 및 FR-02가 감지·보정 대상에서 제외한다.
- 실제 수 시간 벽시계 대기 기반 드리프트 측정. 제어된 절대시각 2~3시간 시나리오만 실행했다.
